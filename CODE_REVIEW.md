# Отчёт код-ревью

Дата ревью: 9 октября 2026 года.

## Итог

Основной сценарий построен понятно: CDP/Playwright снимает сцену, предметный слой
нормализует координаты и расстояния, worker управляет опросом, две SQLite-базы
разделяют географическую историю и точные строки UI. Код уже использовал dataclass,
параметризованные SQL-запросы, экранирование HTML и блокировки соединений.

В ходе ревью исправлены обнаруженные дефекты рабочего поведения, добавлены
docstring/JSDoc, регрессионные тесты и полное описание системы в `README.md`.
После изменений Ruff проходит без замечаний, 14 тестов проходят.

## Оставшиеся замечания

### Высокий приоритет — откат не гарантирован при ошибке записи снимка

`Database.save_snapshot()` (`parsing_site/db.py:343`) и
`TableHistoryDatabase.save_snapshot()` (`parsing_site/table_history_db.py:86`)
выполняют несколько INSERT, а затем явный `commit()`, но не делают `rollback()` при
ошибке в середине последовательности. Соединение останется в незавершённой
транзакции; следующий успешный `commit()` способен зафиксировать частичный снимок.

Рекомендация: оборачивать каждую составную запись в `with self._conn:` внутри
блокировки либо использовать явные `try/except` с `rollback()` и тестом, который
искусственно вызывает ошибку после создания `polls`/`table_snapshots`.

### Средний приоритет — идентичность динамического объекта равна позиции в DOM

JavaScript назначает `index + 1` (`parsing_site/tracking.py:241`), а последующая
история и расчёт перемещения используют этот индекс как ключ. Если целевой сайт
пересортирует маркеры, один физический объект может продолжить траекторию другого.
Сброс предыдущих координат при переподключении уже добавлен, но перестановку внутри
одной сессии он не решает.

Рекомендация: извлекать стабильный идентификатор из `data-*`, `id` или прикладного
атрибута сайта; DOM-индекс оставить только резервным значением. В БД хранить этот
идентификатор отдельно и связывать историю по нему.

### Средний приоритет — история растёт без политики хранения

Каждый опрос добавляет строки сразу в две базы. `storage_stats()`
(`parsing_site/table_history_db.py:142`) оценивает рост, но автоматического удаления,
архивации или ограничения срока нет. При малом интервале и большом числе пар объём
будет расти быстро, а запросы истории — замедляться.

Рекомендация: добавить настройку срока хранения, пакетную очистку старых снимков и
периодический WAL checkpoint; перед удалением предложить экспорт/архив.

### Средний приоритет — ресурсы веб-приложения создаются при импорте

Основная и табличная БД открываются на уровне модуля
(`parsing_site/webapp.py:23-24`), до входа в ASGI lifespan. Импорт модуля уже меняет
файлы на диске, а повторный запуск lifespan того же объекта после закрытия
соединений невозможен. Это осложняет изолированные тесты, reload и встраивание app.

Рекомендация: создавать Database, SettingsStore и ParseWorker внутри lifespan и
класть их в `app.state`; обработчики должны получать зависимости из `Request`.

### Низкий приоритет — универсальный CSV переписывается целиком

`DataProcessor._persist()` читает весь `metrics.csv` в память
(`parsing_site/processor.py:264`) и полностью перезаписывает файл при каждом опросе,
чтобы расширять динамический набор колонок. Время записи растёт линейно, а суммарная
работа — квадратично относительно числа опросов.

Рекомендация: зафиксировать схему метрик, писать строки append-only либо перейти на
SQLite/Parquet с отдельным экспортом CSV.

### Низкий приоритет — офлайн-разбор неполно повторяет режим `percent`

`extract_scene_from_html()` (`parsing_site/html_probe.py:106`) собирает координаты
маркеров в пикселях независимо от режима, тогда как настроенная статичная точка в
`static_to_point()` для `percent` преобразуется через размер карты
(`parsing_site/coordinates.py:152`). Поэтому тест сохранённого HTML в процентном
режиме может сравнить разные системы координат. Основной режим `latlng` не затронут.

Рекомендация: передавать режим в `_collect_markers()` и нормализовать обе стороны
так же, как JavaScript живой страницы; добавить тесты для всех четырёх режимов.

## Исправлено в рамках ревью

- CSV-выгрузка больше не падает из-за дополнительных полей `row_to_dict()`.
- `/api/beep` использует существующий модуль; сигнал вынесен в `sound.py`.
- Настройка звука сохраняется, восстанавливается и снова может быть включена.
- `/api/probe`, как и `/api/test-file`, ограничен каталогом `data_test`.
- Пустой список стационарных точек теперь действительно удаляет все точки.
- После таймаута остановки worker не теряет ссылку на живой поток и не допускает
  параллельный второй worker.
- Предыдущие координаты сбрасываются при переподключении, чтобы не создавать
  ложное перемещение между сайтами/сессиями.
- Значение Leaflet zoom `0` больше не подменяется резервным значением.
- При одинаковом телефоне у разных адресов возвращается правильный исходный адрес.
- Импорт конфигурации больше не печатает служебные пути; сообщения телефонного
  справочника переведены на logging и работают в консоли CP1251.
- Завершение ASGI освобождает ресурсы через `finally`.
- В PyInstaller hidden imports добавлены новые/ранее пропущенные модули истории и
  звука.

## Проверки и пробелы покрытия

Автоматически проверяются миграция/восстановление БД, географическая история,
генерация XLSX, табличная история, CSV-регрессия, настройка звука и совпадение
телефонов. Пока нет автоматических интеграционных тестов CDP/Playwright, HTTP API,
жизненного цикла worker, браузерного JavaScript и PyInstaller-сборки. Для этих
частей нужен отдельный набор с тестовой HTML-картой и управляемым браузером.
